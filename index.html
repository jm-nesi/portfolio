HR back office · Laravel 13 + Livewire 4

HR Portal: integrated HRIS

The internal system HR uses to manage people, attendance and every employee request. I rebuilt it module by module from a legacy plain-PHP site, while the old site kept running on the same live database.

  • Request queues. Leave, time adjustments, overtime, emergency early-out, movement, work-from-home and site transfer. They share one list component, bulk actions and live sidebar counters.
  • Attendance correctness. The legacy summary rewrote remarks every time the page opened, so payroll could read unfinished data. I moved that logic into a single finalizer that runs on save.
  • Safe writes. Anything that touches attendance or leave credits is written only on an explicit HR confirm, and every change is recorded in an audit trail.
  • Design system. Token-based CSS (theme.css → ui.css → page.css) with dark mode. It replaced a 400 KB runtime Tailwind CDN script.
  • Setup tools. Leave credits, leave protocols (daily slot limits per team and shift), HMO eligibility, and trackers for points, regularization and movements.

Employee self-service · Laravel 13 + Tailwind

Employee Portal

The portal every employee uses to time in, check attendance, file requests and download payslips. Team leaders also use it to approve their team's requests. Everything feeds the HR back office in real time.

  • Dashboard. Server clock and time-in, cut-off progress, leave balances, infraction points and announcements.
  • Apply flows. Leave, time adjustment, overtime, emergency early-out and work-from-home, with validation against credits and leave protocols.
  • Approvals. A role-aware menu, so only approvers see team queues, with remarks and a notification inbox.
  • Records. PDF payslips (DomPDF), attendance calendar, infractions, memos and the company handbook.
  • Themes. Light, dark and brand presets, plus seasonal themes an admin can switch on.

Case study

Replacing a legacy HRIS without stopping it

  1. 01

    The situation

    HR, accounting and IT relied on a decade-old plain-PHP site. Each page had its own SQL, and business rules were copied across folders. The database was shared with payroll-facing pages, so it couldn't be taken offline or reshaped.

  2. 02

    The approach

    • I rebuilt one module at a time on a new subdomain, reading the same tables, so HR could switch over page by page.
    • I treated each legacy page as the spec and recorded every rule in a design note. The owner signed off on any change to a pay, attendance or leave rule.
    • Logic lives in services and writer classes, with thin Livewire components.
    • A verified database backup runs before every migration.
  3. 03

    The result

    • Attendance remarks are final when they're saved, not when someone opens a report.
    • All request queues show live counts in one place, so HR no longer checks seven separate pages.
    • One shared visual language, dark mode, and pages that work on a phone.
    • A living design note for each module, so the next developer can pick it up.
How I work

Principles I don't skip

01

Production is sacred

Backups before migrations, writes only on explicit confirmation, and no tests that could touch the live HR database.

02

The legacy code is the spec

I read the old behaviour before rebuilding it, and when a business rule changes, the owner signs off first.

03

Consistency over novelty

Shared components and design tokens, so a fix on one page is a fix on every page.

04

Write it down

Every module has a design note and change log, plus a manual test checklist for the people who use it.
